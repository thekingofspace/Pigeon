Examples

Ten working examples, ordered from the simplest thing you can build to the layer underneath everything else. Each one is complete. You can paste it in and it runs.

Start at the top. Every example only uses ideas from the ones above it, so reading straight down teaches you the whole library. Stop when you have what you need. Most games never get past number six.

1. Tell the server something happened

The smallest useful thing. The client says a button was pressed and the server hears it. Nothing comes back.

Server 
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Pigeon = require(ReplicatedStorage.Pigeon)

local ui = Pigeon.new("Ui")

-- The player who sent it is always the first argument on the server.
ui:On("ButtonPressed", function(player, buttonName)
	print(player.Name, "pressed", buttonName)
end)
Client 
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Pigeon = require(ReplicatedStorage.Pigeon)

local ui = Pigeon.new("Ui")

myButton.Activated:Connect(function()
	ui:Emit("ButtonPressed", "Shop")
end)

Note

There is no Init here. The client only sends, and sending never needs it. Init is only about receiving.

2. Ask the server a question

Call waits for an answer. Whatever the server listener returns is what the client gets back.

Server 
local shop = Pigeon.new("Shop")

shop:On("Buy", function(player, itemId)
	local price = PRICES[itemId]
	if not price then
		return false, "no such item"
	end
	if getCoins(player) < price then
		return false, "not enough coins"
	end

	takeCoins(player, price)
	giveItem(player, itemId)
	return true
end)
Client 
local shop = Pigeon.new("Shop")

-- This yields until the server answers, or until the call times out.
local ok, reason = shop:Call("Buy", "sword")

if ok then
	showToast("Bought!")
else
	showToast("Could not buy: " .. reason)
end

The server never has to send a reply itself. Returning from the listener is the reply. If the listener errors, or nothing is listening, the call gives up after the timeout and returns nil.

3. A live scoreboard

Now the server starts the conversation. This is the first example that needs Init, because the client is receiving.

Server 
local scores = Pigeon.new("Scores")

local function onScoreChanged(board)
	-- Goes to every player in the game.
	scores:Broadcast("Updated", board)
end

-- Send the current board to one player when they join.
Players.PlayerAdded:Connect(function(player)
	scores:BroadcastTo({ player }, "Updated", getBoard())
end)
Client 
local scores = Pigeon.new("Scores")

scores:On("Updated", function(board)
	redrawScoreboard(board)
end)

-- Handlers are in place, so let the server start sending.
scores:Init()

Careful

Register every On you care about first, then call Init once. Anything the server sent before that is held for you and arrives in order the moment you call it. See Startup and Buffering.

4. Party chat

A room is a named list of players on one carrier. You send to the list instead of to everyone.

Server 
local party = Pigeon.new("Party")

party:On("Create", function(player, partyId)
	party:CreateRoom(partyId, { player })
	return true
end)

party:On("Join", function(player, partyId)
	party:JoinRoom(partyId, player)
	party:SendToRoom(partyId, "Joined", player.Name)
	return true
end)

party:On("Say", function(player, partyId, message)
	party:SendToRoom(partyId, "Message", player.Name, message)
end)

party:On("Leave", function(player, partyId)
	party:LeaveRoom(partyId, player)
end)
Client 
local party = Pigeon.new("Party")

party:On("Message", function(who, message)
	addChatLine(who .. ": " .. message)
end)

party:On("Joined", function(who)
	addChatLine(who .. " joined the party.")
end)

party:Init()

party:Call("Join", "party-42")
party:Emit("Say", "party-42", "hello everyone")

Rooms are server side only. The client has no idea they exist, it just asks to be put in one. Players are taken out of every room automatically when they leave the game. See Rooms.

5. A staff only channel

A guard closes a channel in both directions. Until a player passes it they cannot send on the channel, and they are left out of every broadcast on it. That is what makes a broadcast here safe.

Server 
local staff = Pigeon.new("Staff")

-- Installing a guard closes the channel to everyone straight away.
staff:UseHandshake(function(player)
	return isStaff(player)
end)

staff:On("Kick", function(player, targetName)
	local target = Players:FindFirstChild(targetName)
	if target then
		target:Kick("Removed by staff.")
	end
end)

-- Only players the guard let in will ever see this.
staff:Broadcast("Alert", "Server restarting in 5 minutes")
Client 
local staff = Pigeon.new("Staff")

staff:On("Alert", function(message)
	showStaffAlert(message)
end)

staff:Init()

-- Yields until the server's guard decides.
if staff:Handshake() then
	openStaffPanel()
end

A normal player calling Handshake gets false and stays shut out. They can call it as often as they like and it will keep saying no. See Handshakes.

6. Player stats that stay in sync

A staged table is a plain table whose changes replicate. Write to it on the server and the clients holding it see the write. There is no sync code.

Server 
local data = Pigeon.new("Data")

Players.PlayerAdded:Connect(function(player)
	local stats = Pigeon.StagedTable({
		coins = 0,
		level = 1,
		combat = { health = 100, armour = 0 },
	})

	-- Only this player may ask for their own stats.
	stats:UseCapture(function(who)
		return who == player
	end)

	data:CaptureTable("stats-" .. player.UserId, stats)
	profiles[player] = stats
end)

-- Anywhere later. Every write replicates on its own.
local function reward(player, coins)
	local view = profiles[player]:GetTable()
	view.coins = view.coins + coins
	view.combat.health = 100
end
Client 
local data = Pigeon.new("Data"):Init()

-- Yields the first time. After that it is cached and free.
local stats = data:RequestTable("stats-" .. Players.LocalPlayer.UserId)
local view = stats:GetTable()

print(view.coins)
print(view.combat.health)

Several writes in the same frame are sent as one message, so filling a table field by field costs one send and not one per field.

Careful

The client's copy is a mirror, so treat it as read only. view.coins = 999 on the client changes what that client sees and nothing else, and the next patch touching coins wipes it out. If a client needs something changed, send a message and let the server write. See Staged Tables.

7. A combat system you can switch off

Related channels can share one transformer. Destroying it drops all of them, and every listener on them, in one call. This is how you turn a whole system off.

Server 
local combat = Pigeon.Transformer("Combat")

local damage = Pigeon.new("Damage", { Transformer = combat })
local status = Pigeon.new("Status", { Transformer = combat })
local effects = Pigeon.new("Effects", { Transformer = combat })

damage:On("Hit", function(player, targetId, amount)
	applyDamage(player, targetId, amount)
end)

status:On("Request", function(player)
	return getStatus(player)
end)

-- The round is over. One call drops all three channels.
local function endRound()
	combat:Destroy()
end
Client 
-- The client builds its own transformer with the same id.
local combat = Pigeon.Transformer("Combat")

local damage = Pigeon.new("Damage", { Transformer = combat }):Init()
local effects = Pigeon.new("Effects", { Transformer = combat }):Init()

effects:On("Play", playEffect)

local function leaveMatch()
	combat:Destroy()
end

The three channels stay separate. A message on "Damage" is never heard by "Status", even though they ride the same RemoteEvent. See Transformers.

8. Logging and rate limiting

Middleware sees every packet on a channel and can change it. This logs everything coming in and blocks a player who is sending too fast.

Server 
local chat = Pigeon.new("Chat")

local lastSent = {}

chat:UseIncoming(function(direction, event, args, player)
	print(direction, event, player and player.Name)

	if event == "Say" then
		local now = os.clock()
		if lastSent[player] and now - lastSent[player] < 0.5 then
			-- Rewrite it into an event nothing listens for, which drops it.
			return "Ignored", args
		end
		lastSent[player] = now
	end

	-- Returning nothing leaves the packet exactly as it was.
	return nil
end)

chat:On("Say", function(player, message)
	chat:Broadcast("Said", player.Name, message)
end)
Client 
local chat = Pigeon.new("Chat")

-- Stamp the time onto everything that leaves this machine.
chat:UseOutgoing(function(direction, event, args)
	local copy = table.clone(args)
	table.insert(copy, os.clock())
	return nil, copy
end)

chat:On("Said", function(who, message, sentAt)
	addChatLine(who, message, sentAt)
end)

chat:Init()

chat:Emit("Say", "hello")

Careful

Middleware runs for every packet on the channel, including events nothing has a listener for. Renaming one onto an event you do listen for is what makes it arrive, and renaming it onto a name nothing listens for is what drops it. See Middleware.

9. Streaming a position

For things you send constantly and do not mind losing, an unreliable carrier is cheaper. A dropped position does not matter because another one is right behind it.

Server 
local tracking = Pigeon.new("Tracking", { Unreliable = true })

RunService.Heartbeat:Connect(function()
	for _, player in Players:GetPlayers() do
		tracking:BroadcastExcept({ player }, "Moved", player.UserId, getPosition(player))
	end
end)
Client 
local tracking = Pigeon.new("Tracking", { Unreliable = true })

tracking:On("Moved", function(userId, position)
	moveGhost(userId, position)
end)

tracking:Init()

Never put anything that must arrive on an unreliable carrier. Coins, inventory and damage all belong on a normal one. Note that Call and every reply always take the reliable lane anyway, whatever the carrier says. See Unreliable Sending.

10. Talking to the transport

This is the bottom. Pigeon.Network is the layer carriers are built on. You almost never want it, but it is public, and it is how you check on the health of the system.

Carriers add channel names, middleware, guards and rooms on top of this. If you use the transport directly you get none of that, and you have to pick your own event names carefully so they do not collide.

Server 
local Network = Pigeon.Network

local transformer = Pigeon.Transformer("RawExample")

-- Server callbacks get the player, the transformer id, then the payload.
local disconnect = Network.Receive("raw-event", function(player, transformerId, data)
	print(player.Name, "sent", data)
end)

Network.Broadcast(Players:GetPlayers(), transformer, "raw-event", { hello = true })

-- Later.
disconnect()
Client 
local Network = Pigeon.Network

local transformer = Pigeon.Transformer("RawExample")

-- Client callbacks have no player, so the transformer id comes first.
Network.Receive("raw-event", function(transformerId, data)
	print("got", data)
end)

-- Ready is what Init does underneath. The channel is the part of the name before
-- the NUL byte, and there is none here, so the channel is "raw-event" itself.
-- Without this the server's Broadcast just sits in the buffer for this client.
Network.Ready(transformer, "raw-event")

Network.Push(transformer, "raw-event", { hello = true })

Checking for leaks

Network.Diagnostics counts what the transport is holding. Every figure should settle. A number that only ever grows is a leak. 

local before = Pigeon.Network.Diagnostics()

startMySystem()
stopMySystem()

task.wait(1)

local after = Pigeon.Network.Diagnostics()
print("listeners:", before.listeners, "->", after.listeners)
print("pending:", after.pending)

If listeners does not come back down after you tear a system down, something is still connected. See Cleanup and the Network reference.
